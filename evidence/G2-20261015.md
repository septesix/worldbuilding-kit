# G2 — the length cap fails by drift, so the rule became a comparison

Date: 2026-10-15 · guidance key: **`488984d6`** (was `5fc04d12`, before that `e571ec50`) · spec_rev: R-15

## What was wrong

`words_per_turn: 170` held in single-turn runs (128–164, n=4) and failed in multi-turn ones - in both
arms. It was never measured in the mode it was being applied to. Across the corpus the failure is not
disobedience but growth: scored turns run ~140 words in the first turns of a session and ~200 by turn
seven, and the rate over cap climbs 14% → 21% → 35% → 42% → 35% → 60% → 66% by turn index. The writer
gets a wall of text with the question buried at the bottom, and the number that was supposed to prevent
it was obeyed for the first three turns and then simply stopped being looked at.

The scenario that showed it worst was `retcon` in the skill arm: five turns, **all five over**, at
171 / 242 / 195 / 199 / 250.

## What changed

The cap is untouched. 170 stays 170 - raising it would launder drift into a quota, and the failure is
attention, not arithmetic. What changed is where the rule sits and what it compares against:

- **`SKILL.md`**, in the `write back · reflect` bullet - the step where the model is already assembling
  output: "Beats stay inside `beat_budget`; **longer than last turn? cut a beat.**" This is the I4/I5
  lesson applied: the same rule, phrased once in a place the model looks while it needs it, beat four
  phrasings in a place it reads before it decides.
- **`references/voice.md`**, rule 1: the failure is named as drift rather than excess, with the measured
  profile beside it, and the instruction to compare before sending - cut the longest beat, leave the
  question whole.
- **`references/rubric.md`**, the word-budget argument: `words_per_turn` was measured in single turns and
  does not hold in the mode where prose grows; "a number that was only ever measured in one mode is a
  guess in the other." Read last turn's length off the log; if you are growing, cut the longest beat.

New guard: the cut instruction must appear in ≥3 shipped files and the comparison in ≥2. Proven to fail
both ways before being trusted - deleting the hook from `SKILL.md` gave `cut in 2 files, comparison in 1`;
deleting the cut line from two files gave `cut in 1`; either alone fails. `SKILL.md` stayed at 499 words
under the cap by offsetting the addition against four trims that carried no rule.
