## Why it mattered more than naming hygiene

The slug is an address, not a label: `[[links]]` point at it, the scoreboard counts it, and the entity's
canon lives in that file. Two entities deriving `encyclopedia/severin.md` means the second write deletes
the first one's facts — the one operation the append-only rule exists to forbid, and the file-level half of
F6 was already asserting that rule in prose. Before this commit the promise lived **only** in §7:

## The gate, proven on a directory

`seedcheck.identity()` requires every `[[link]]` in a seeded world to resolve to **exactly one** entity
file, where a bare `[[stem]]` is allowed to find `stem-kind.md` — because that is what disambiguation
produces. Zero targets is dangling, several is ambiguous, and both mean the writer is about to be told
about an entity they cannot open.

Both sides run against a real seeded directory, not a string: clean seed → bit 16 clear (a gate that
false-reds good runs gets ignored); one dangling link plus one link matching `twin-place` *and*
`twin-person` → bit 16 set. The **suffix/kind drift** half deliberately stayed out of run-time checks: a
title that legitimately ends in a kind word (`ledger-text`) would fail a good run, so it is asserted
statically against the shipped fixture instead, where the vocabulary is ours.

Corpus count, because it changes the finding: **0 of 74 artifacts contain two same-stem entities inside one
world.** My first sweep said "one collision (`tollhouse`)" — that was an aggregation across separate temp
dirs: `tollhouse-institution` in two `new-world` runs, `tollhouse-place` in one `close` run. Different
worlds, no collision. So the rule is being written before the failure, which is the right order, and the
certification set is where it either stays theoretical or doesn't.

## Two findings that came out of doing it

**A stale literal in guidance.** `SKILL.md` still said options are "≤18 words" after R-26 moved
`option_words` to 19 — a number where a tunable name belongs, i.e. provenance drift on the prose side, in
the one file every run reads. Now it says `≤option_words`, and a guard fails if `SKILL.md` or
`references/` contains a hard-coded option length again. This is the third instance of the same failure in
two days (folklore numbers in a table, folklore in a spec, folklore in an instruction).

**Two quiet mistakes of mine, recorded because both were invisible to the tests.** The place-count guard I
wrote searched for `collidi`, which matches "colliding" and not "collision": it reported the rule stated in
1 place when it was stated in 3. And trimming a SKILL phrase to stay under the word cap broke the F6 guard
keying on `"never delete one under"` — the mirror image of the same hazard: a guard that reads prose
literally is right about the prose and silent about the rule. Both guards now key on stems that hold for
the whole family (`-e collis -e collid`), and the fixture-first ordering kept the F6 assertion honest while
I moved its words.
