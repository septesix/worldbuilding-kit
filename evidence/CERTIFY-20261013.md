## Defects in the harness, found by this batch (unfixed, deliberately)

1. `reviewcheck.py` exits **4** for NOT-GRADED while its own documented bitmask uses 4 for "review
   delivered but never logged". `run.sh` tests both `[ "$RRC" = 4 ]` and `[ $((RRC & 7)) != 0 ]`, so the
   same integer means "nothing was examined" and "the marker is missing" simultaneously.
2. `run.sh` writes the string `INFRA-FAIL` into the artifact it grades, and `reviewcheck` tests `if
   'INFRA-FAIL' in t` — so re-grading such a file returns NOT-GRADED forever. The detector reads its own
   output. Two files in this batch are already in that state.
3. `wordcount.py` skips multi-turn files, while `behavior` selects them into its list. The result reads
   as `skip ... (no transcript)`, which is correct but easy to mistake for an aborted run; the gate that
   actually grades them is `check.sh multi`, and it is opt-in.

## Addendum: the three defects are fixed (same day, key still e571ec50)

Why run.sh wrote into the file it grades: the evidence file is deliberately one self-describing record -
prompt, transcript, world dump, verdicts - so a human can read a run in one place. The graders were then
pointed at that same record, and `run.sh`/`multiturn.sh` echoed verdict lines into a stream that was still
open. So it was not carelessness about where to write; it was one artifact serving two readers, with the
writers and the readers unable to tell each other apart. The fix keeps the single file and separates the
two roles: verdicts are computed after the artifact closes and appended under `## harness verdicts`, and
everything that scans an artifact calls `harness_markers.strip()` first.

- **Exit-code collision** - NOT-GRADED is now 64, outside the finding bitmask, in reviewcheck, canoncheck
  and wordcount. Bit 4 stays a finding. The old code returned 4 for both and `run.sh` tested both readings
  of the same byte, which is how a real breach got reported as infrastructure noise.
- **Self-poisoning** - `reviewcheck` decided an aborted run by substring-matching `INFRA-FAIL`, and
  decided the marker-missing finding with the literal `provoked: review` that its own failure message
  contains. Both readings now come from typed data (`## pi exit status:`) with one exception kept on
  purpose: an `INFRA-FAIL` line at the start of a line still counts as "did not happen", because older
  artifacts recorded aborts only in prose, and stripping it away would have turned an aborted run into
  clean evidence. Re-grading is idempotent: two passes, identical output.
- **Coverage hole** - wordcount returned None for multi-turn files while `behavior` listed them, so the
  length cap was never measured in the mode where prose grows; a run where every file is skipped now
  exits 64 instead of a silent 0.

Fixing the third item surfaced a fourth, worth more than the rest: **the two gates disagreed about the
same quantity.** wordcount said the retcon run's worst turn was 259 words, invariants said 250, on the
same file. The cause was that my new multi-turn path counted the harness's own `writer:` echo - the
scripted prompt line - as model prose. `invariants` was right; my change was wrong. Turn words are now
counted identically, and a selftest fails if the instruments ever drift apart on a real artifact.

Suite: 170 to **178 assertions**, 0 failures - and the last of those is a guard that compares

## Correction (same day, later): the review-marker finding was false

`supersedes:` the claim in the addendum above that `review-owed` re-graded to bit 4, and that 1 of 3
review runs breached the review contract. Neither is true.

The run logged its review the way runs log every other provoked type - as an item in the machine line's
list: `- turn: 1 · provoked: discovery, review · targeted: daily-life`. `reviewcheck` tested for the
joined literal `provoked: review`, so a compliant line read as "never logged", and `sessions_since_review`
missed it too, which inflated the owed gap at the same time. `SKILL.md:59` shows the field as singular
(`provoked: <type>`) while `rubric.md:108` calls review "one of the eight types" recorded there, and real
runs write lists. The detector had picked a spelling and graded the other one as a breach.

What changed: the marker is now matched as a *field inside a machine line* - a line carrying the `·`
separator, with `review` in the provoked list - in either spelling, plus the pre-R-9 shape. Prose that
merely quotes the marker ("count the sessions after the last line carrying `provoked: review`") no longer
counts: mentioning is not doing, which is the same confusion this file keeps meeting in new clothes.

The finding, restated honestly: `behavior` now reports **the recorded review runs met the contract**, and
the batch's real review findings are unaffected - `review-owed/skill` delivered a 5-item memo and logged
it. What remains genuinely open on the review side is a *documentation* ambiguity in the guidance, not a
behaviour failure, and it has been left alone because editing guidance moves the key and voids the
evidence below it.

Also recorded, because it is the interesting part: this false red entered the report through an
**aggregate that grepped stored verdict text** (`grep -lE 'REVIEW-OWED|REVIEW-FAIL'` over the artifacts).
After the grammar fix the file still read as breached, because the count was tallying what last week's
detector had written into the record rather than re-deriving from it. That is the self-reference defect
one layer up: a verdict citing an older verdict as evidence. `behavior` re-derives review verdicts now,
and separates three outcomes that used to blur - clean, `not graded`, `instrument crash` - after an early
draft of the loop turned a redirect failure into `3 of 3 breached`, because `$TMP` is not defined in that
function and `128`/`1` both fell into the breach branch.
