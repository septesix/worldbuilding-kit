# G6 — one machine line per turn that happened

Date: 2026-10-15 · guidance key: **`c8359411`** (was `52805797`)

## Cause, and why the fixture stayed put

The `cadence` run in G3 wrote **eight** machine lines for four turns, numbered 5 to 12, three annotated
"late entry", naming pillars no turn had chosen. The reason was in the prop, not the model: the
established fixture's `log.md` contains four session headers and **zero** machine lines, while its
`index.md` declares `turns_per_session: 12`. A resumed session opened a ledger claiming ~48 turns of
history with no record of any of them, and the model resolved the contradiction the only way an
append-only file allows - by inventing the missing rows. Nothing in the guidance forbade that.

The fixture was left exactly as it is. A world with a hole in its ledger is what this skill will meet in
practice - machine lines arrived late in this project's own history (R-9) - and the run that caught the
defect is worth more than a run that hides it. The prop is a stress case, not a bug.

## What changed

- `SKILL.md`, where the ledger rule already lives: "one machine line per **turn that happened**".
- `references/rubric.md`: a new paragraph beside the rule about *reading* a hole, forbidding *writing over*
  one - an invented line is permanent, and every window rule then reads a history that never occurred,
  which is worse than the hole, because the hole was honest about being unknown.
- `assets/index-template.md`, the section a model sees when it creates the file: same three words.

Guard: the phrase in ≥3 shipped files and the prohibition in ≥1, since a rule stated once in a file that
may not be open is a suggestion. Proven to fail - thinning it to one file gave `ledger-fidelity rule thin:
'per turn that happened' in 1 files`. `SKILL.md` at 497 words.
